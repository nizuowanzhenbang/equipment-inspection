# PostgreSQL 点检写入可靠性

本轮落实已批准的长期路线中的数据库可靠性阶段。验收面向软件行为，不以用户学习进度为条件。

## 范围与行为

- 保留任务与测点业务幂等键，同账户同内容重传返回原记录，冲突返回 409。
- 在真实 PostgreSQL 中验证上述行为、唯一约束、事务回滚和既有索引升级。
- 不同任务同时生成缺陷时，不得因为 count + 1 取得相同单号而失败。手动上报与自动生成使用相同的安全编号策略。
- 同设备两次不同的异常记录必须累计扣分，0 分不能被当成缺省 100 分。
- 测试使用专用 TEST_POSTGRESQL_URL，在随机独立 schema 建表和清理；不用应用 DATABASE_URL，不启动应用 lifespan 或外部集成。
- CI 除既有 SQLite、前端和演示检查外，增加 PostgreSQL 16 检查及测试结果文件。

## 最小实现

运行时缺陷编号采用 DF-YYYYMMDD-<32 位 UUID>，继续使用现有 50 字符列与唯一索引；旧编号不改写，显式传序号的种子生成保持兼容。编号不再承诺当日连续。完整 UUID 的碰撞概率极低，数据库唯一约束仍是最终保护，并非数学上的无碰撞保证。

点检扣分使用数据库内的原子 UPDATE / CASE / COALESCE，并在原有记录、缺陷和任务事务中提交。正常记录与幂等重传不扣分。健康度为 NULL 时保留缺省 100 规则，0 分保持 0。

本轮不宣称全面解决其他工作流的并发问题；验收恢复健康度、批量任务编号、跨系统消息交付和正式版本迁移作为后续候选。无新表或历史数据重写。

## 验收

SQLite 原有测试及新增零分、旧单号碰撞回归通过；PostgreSQL 真正并发请求验证幂等、冲突、两任务共享设备和手动/自动创建；约束失败不得留下半条业务链；重复索引初始化安全，旧重复数据被拒绝且保留。前端和 API 演示保持通过。证据注明数据库版本、提交和覆盖边界。
