# 第 4 轮：可重复部署与依赖维护

上一轮 PR #7 / 7f367b7 三项 CI 通过后进入本轮。用户要求完成后直接进入下一轮并代做常规决策。

## 决策

1. 固定验证后的 Python 运行与开发依赖（含散列），前端使用 npm ci 和 lockfile；Docker 基础镜像按实际 registry digest 固定。仅做必要兼容升级，记录扫描结果，不混入大版本业务重写。
2. Compose 默认演示使用本地上传，减少必须启动的服务；S3/MinIO 保留为显式配置的外部服务。默认关闭调度器避免演示首次启动产生难以复现的后台变化，可显式开启。
3. 增加 Docker Compose 冷启动 CI，使用独立项目/临时 volume；验证健康、数据库就绪，再用真实 Chromium 登录、访问设备列表并核对通过 API 创建的模拟设备。保留截图/trace，清理仅限该次 CI 项目。
4. 增加 /ready 就绪检查（数据库连接和迁移版本），保留 /health 存活接口。请求返回 X-Request-ID，记录请求 ID、方法、路径、状态、耗时；不记录 token、query、请求体、密码或原始异常字符串。
5. 本机无 Docker 可执行文件，容器冷启动由远程 CI 验证；本地运行锁定依赖测试、构建及必要浏览器验证，不将本地非 Docker 启动说成容器验收。

## 验收

锁定依赖的全量测试通过；前端构建及离线回归通过；就绪失败返回 503 且无连接细节；请求 ID 合法且出现在日志/响应；干净 Compose 环境通过浏览器冒烟；扫描结果明确列出已处理和剩余项。独立审查后提交新 PR，检查最终提交 CI。

Ruling: Docker Hub 的 minio/minio 元数据返回 404、manifest 返回 401，无法核实可拉取 digest；本轮不保留未经验证的内置镜像，原有 S3 实现和配置接口保留。已有 MinIO volume 不删除，需自行连接已验证外部服务；代价是对象存储不再一条命令随演示启动。
