# 数据库版本迁移与兼容矩阵

## 运行顺序

配置连接及正式模式密钥后，在 backend 目录执行：

```sh
python -m app.migrate upgrade
python -m app.migrate check
python -m app.bootstrap_admin --username operator
uvicorn app.main:app --port 8003
```

`upgrade` 使用 DATABASE_URL 对应的库，需维护窗口停止其他应用写入，并先生成和验证备份。`check` 不执行 DDL。正式启动若版本缺失或结构不匹配会失败；演示启动及 seed_data 显式调用同一升级入口。

三个冻结版本是 `0001_frozen_baseline`、`0002_legacy_additions` 和当前 HEAD `0003_purchase_receipts`。基线保存第 2 轮 dfb394b 的 14 张表结构，不导入可变 ORM。第二步只补已知历史签名字段与点检唯一索引；新空库已具备这些项时不会重复添加。第三步新增采购收货成功快照表及独立方言增量合同，原十四表合同保持不变。

## 支持范围

| 数据库形态 | 处理 |
|---|---|
| 空库 | 创建冻结基线并记录目标版本 |
| 第 2 轮完整未版本化库 | 精确检查后纳入版本管理，保留数据 |
| 第 2 轮仅 users/audit_logs 的初始化库 | 检查两表后补齐其余基线表 |
| 完整表集，仅缺两票 signatures 列和/或点检任务测点唯一索引 | 先检查所有其他结构，再补已知缺项 |
| 0002 版本，原十四表结构完整 | 保留已有数据，事务内创建收货表并升级到 0003 |
| 当前 0003 缺收货表，或 0002 有结构漂移 | 拒绝，不自动修补或覆盖版本 |
| 已处于目标版本 | 复核结构，可重复运行，不重置数据 |
| 未知列、表、类型/长度、可空性、主外键、索引、检查约束、视图、触发器等差异 | 拒绝自动升级，先人工核对 |
| 重复任务测点记录 | 拒绝，保留全部记录，不自动删除 |
| 未知版本或不完整版本标记 | 拒绝，不直接 stamp 覆盖 |

这是声明的结构矩阵，不代表任意历史版本都能直接升级。数据库必须专用于本应用；PG 使用连接的当前 schema。合同覆盖应用表及关键关联/索引，不能代替对整个集群权限、扩展、函数和部署设置的审查。

SQLite 额外检查反射可能遗漏的表达式索引、排序及 collation；PG 检查主键 serial 默认值确实引用当前表拥有的序列。不能用错误结构上的正确版本字符串绕过检查。

## 事务与失败

SQLite 显式 BEGIN IMMEDIATE，PostgreSQL 使用事务 advisory lock。预检、Alembic DDL、版本标记与后检通过同一连接/事务执行；失败回滚。锁仅协调本应用迁移和初始化工具，不能阻止绕过协议的外部 DDL/应用写入，所以仍需维护窗口。

测试在补字段后故意让数据库执行非法 SQL，验证新增字段、索引与版本标记全部回滚，再解除故障重试。独立审查发现的 SQLite 隐藏索引及 PG 错误序列引用，也有明确拒绝用例。

迁移入口使用 Alembic 官方的 [共享连接事务方式](https://alembic.sqlalchemy.org/en/latest/cookbook.html#sharing-a-connection-across-one-or-more-programmatic-migration-commands)。直接执行未经过预检的 Alembic 命令被禁止。后续结构修改应追加迁移并更新相应版本合同，不修改已发布基线来冒充兼容。

## 备份和恢复证据

见 [备份与恢复工具](BACKUP-RESTORE.md)。恢复测试在 SQLite 新文件和 PostgreSQL 独立数据库中进行：

1. 备份包含用户、设备、路线、测点、任务、点检记录、待验收缺陷和版本标记的应用库。
2. 验证恢复的表行数与外键，检查记录到测点/设备/缺陷的关联和原始发现内容。
3. 真实登录并关闭恢复前已有的待验收缺陷，分数由 80 恢复为 83。
4. 再运行完整 API 点检—派工—修复—驳回—重修—验收场景。
5. 原来源库仍保留待验收状态和 80 分，证明业务操作发生在恢复库。

旧 0002 备份恢复到独立库后须显式升级到 0003，才能接入当前应用。

这是模拟数据的 API/数据库演练，不是浏览器验收、全部灾备或现场恢复认证。备份不包含对象存储附件、环境密钥、全局数据库角色及外部系统。

## 回退

本轮不提供删除表/列的自动 downgrade。代码 revert 不等于数据恢复；需要回退数据时，先将备份恢复到独立库并验证，再由部署流程切换连接。恢复工具不会覆盖当前数据库，也不会自动切换业务流量。
