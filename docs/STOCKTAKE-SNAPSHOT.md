# 盘点快照与库存版本

2026-10-04，基于 PR #13 的 main `170b8393e622d31e23a5a546419748183f07ce20`。本轮无新增迁移或依赖，数据库 HEAD 保持 `0003_purchase_receipts`。

## 问题与当前行为

页面读取库存10，期间另一人员入库2到12，旧页面提交绝对盘点10，会覆盖新增2。现有备件锁能串行写入，但不能识别操作人读取库存的时点。

备件响应现在包含 `stock_revision`，取同备件最后一条已提交库存流水ID，无流水为0。库存数量和版本由同一SELECT返回；出入库及首次采购收货产生流水，成功UUID重放和物料名称等元数据更新不改变版本。不同备件的流水不影响当前版本；数量先增加再减少回原值，版本仍已改变。

ADJUST提交 `expected_stock_revision`，备件锁后刷新再比较。匹配则按既有绝对库存语义登记，包括归零；不匹配409，不更新库存或追加流水。同版本重复/并发盘点只能一次成功，即使目标数量等于现有库存也会生成新版本。库存与流水同事务，真实流水写入失败回滚后原版本可重试。

出入库成功响应的库存、流水和版本在提交前固定，不能被后来事务修改。原采购收货UUID快照、权限与合法部分到货取消继续保留。

## API与旧客户端

创建、列表、详情、更新备件响应都有整数 `stock_revision`。盘点请求示例（版本使用实际读取结果）：

```json
{"movement_type":"ADJUST","qty":0,"expected_stock_revision":42}
```

版本要求JSON整数 `0..2147483647`，布尔、浮点、字符串、负数和超限值422。ADJUST缺失/null返回409：“盘点信息不完整，请更新客户端并刷新库存后重新盘点”；过时返回409：“库存已有变动，请关闭并刷新库存，核对后重新盘点”。IN/OUT可省略版本，数量、关联对象及角色规则沿用。

旧盘点客户端必须升级后读取版本，服务端不继续接受无校验绝对盘点；这是有意的兼容变化。若旧客户端无此字段，应更新客户端，不能改成循环重发或每次提交前自动替换版本。其他旧出入库/收货客户端保持原约定。

## 页面操作

打开出入库时固定显示的库存及版本，选择盘点会清空数量要求显式输入。冲突保持原基准和输入，不自动换版本或重试。点击“关闭并刷新库存”，再打开、核对并输入新数量；取消或重新打开也清空旧表单。请求等待响应时保持该对话框，禁用编辑/关闭，避免旧响应关闭另一项新操作。
